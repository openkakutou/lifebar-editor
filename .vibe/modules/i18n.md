# Module: i18n
**Role:** This app's localization setup (backlog item 009): wires `web-ui-kit`'s shared i18next integration layer (`initI18n`) under this app's own namespace (`"lifebar-editor"`) and its own `localStorage` key (`"lifebar-editor-locale"`, not the shared default — every OpenKakutou app deploys on the same GitHub Pages origin, so sharing it would leak one app's language choice into every other one), plus a thin `t(key, defaultValue, vars?)` wrapper mirroring `web-ui-kit`'s own `t()` contract. `t()` returns the interpolated `defaultValue` verbatim whenever `initAppI18n` hasn't resolved yet in this page — every call site's `defaultValue` matches its `en.json` entry character for character, so the large majority of this app's existing tests never need to bootstrap i18n at all. `en.json`/`fr.json` hold this app's own message catalogs, namespaced by area (`app`, `errors`, `actions`, `elements`, `input.lifebar`, `input.spriteSheet`, `wizard` — including each bundled template's own label by its stable `id` — `saveExport`, `validation`, `sprites`, `shortcuts`). The app's own brand name ("Lifebar Editor") is deliberately never translated, treated as a proper noun. See `.vibe/decisions/009-i18n-integration-approach.md` for the full design rationale, including how live-switching responsibility is split by how much state a full re-render would otherwise destroy.
**Files:** `src/i18n/i18n.ts`, `src/i18n/en.json`, `src/i18n/fr.json`
**Exports:** `NAMESPACE: string`, `STORAGE_KEY: string`, `initAppI18n(): Promise<I18nInstance>`, `t(key, defaultValue, vars?): string`, `getI18n(): I18nInstance | undefined` (re-exported from `web-ui-kit`), `onLocaleChange(callback): () => void` (re-exported from `web-ui-kit`)
**Depends on:** `@openkakutou/web-ui-kit` (`initI18n`, `getI18n`, `onLocaleChange`, `LocaleCatalogs`, `WuikLocaleSwitcherElement`, external package — typed locally in `src/types/web-ui-kit.d.ts` since the installed package ships no `.d.ts` of its own; a structural `I18nInstance` interface is declared there rather than importing `i18next`'s own type, since doing so — even type-only, even unused — was confirmed to make `tsc` silently fail to merge the ambient `declare module` block)
