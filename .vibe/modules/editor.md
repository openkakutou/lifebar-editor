# Module: editor
**Role:** The elements editor (backlog item 004): lets the user select any parsed lifebar Section and edit its Entries in place, assigning a sprite to any Entry that references one (identified by a `.spr` key suffix, per `.vibe/decisions/004`) via a picker over an already-loaded sprite sheet's metadata. Sections render as collapsible panels, flagged on their own (possibly collapsed) header when a sprite reference needs attention, so an error/prompt state is never hidden inside an unopened panel. The save/export screen (backlog item 005) is here too: `export-validation.ts` finds every reason the document isn't safe to export yet (a `;` in a value — blocking, not overridable; an unresolved `.spr` reference — a warning, overridable), and `save-export.ts` wires a button to `lifebar.serializeLifebar` and a browser download, gated by that check — see `.vibe/decisions/005`.
**Files:** `src/editor/sprite-reference.ts`, `src/editor/elements-editor.ts`, `src/editor/export-validation.ts`, `src/editor/save-export.ts`
**Exports:** `isSpriteReferenceKey(key): boolean`, `parseSpriteReference(value): ParsedSpriteReference`, `formatSpriteReference(group, image): string`, `findSprite(spriteGroups, group, image): Sprite | null`, `resolveSpriteReference(value, spriteGroups): SpriteReferenceStatus`, `renderElementsEditor(root, document, spriteGroups, options?): void`, `ElementsEditorOptions`, `findExportProblems(document, spriteGroups): ExportProblem[]`, `ExportProblem`, `renderSaveExport(root, options?): void`, `SaveExportOptions`, `defaultTriggerDownload(text, fileName): void`
**Depends on:** `modules/lifebar.md` (`LifebarDocument`/`LifebarSection` types, `serializeLifebar`), `modules/wasm.md` (`SpriteGroup`/`Sprite` types), `modules/document.md` (the document/sprite-sheet stores `save-export.ts` reads from)
