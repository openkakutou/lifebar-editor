# Module: editor
**Role:** The elements editor (backlog item 004): lets the user select any parsed lifebar Section and edit its Entries in place, assigning a sprite to any Entry that references one (identified by a `.spr` key suffix, per `.vibe/decisions/004`) via a picker over an already-loaded sprite sheet's metadata. Sections render as collapsible panels, flagged on their own (possibly collapsed) header when a sprite reference needs attention, so an error/prompt state is never hidden inside an unopened panel. Committing an Entry's value calls `onEntryChange` with both the previous and the new value (item 007 extended this from new-value-only), so a caller can build an undo step from it — the document itself is still always mutated in place regardless of whether a caller supplies that callback. The save/export screen (backlog item 005) is here too: `export-validation.ts` finds every reason the document isn't safe to export yet (a `;` in a value — blocking, not overridable; an unresolved `.spr` reference — a warning, overridable), and `save-export.ts` wires a button to `lifebar.serializeLifebar` and a browser download, gated by that check — see `.vibe/decisions/005`. `undo-redo-controls.ts` (item 007) is a thin, separate view over `document`'s shared `CommandStack`: two toolbar buttons whose disabled state is the undo/redo history's only visible representation, with no history of their own.
**Files:** `src/editor/sprite-reference.ts`, `src/editor/elements-editor.ts`, `src/editor/export-validation.ts`, `src/editor/save-export.ts`, `src/editor/undo-redo-controls.ts`
**Exports:** `isSpriteReferenceKey(key): boolean`, `parseSpriteReference(value): ParsedSpriteReference`, `formatSpriteReference(group, image): string`, `findSprite(spriteGroups, group, image): Sprite | null`, `resolveSpriteReference(value, spriteGroups): SpriteReferenceStatus`, `renderElementsEditor(root, document, spriteGroups, options?): void`, `ElementsEditorOptions`, `findExportProblems(document, spriteGroups): ExportProblem[]`, `ExportProblem`, `renderSaveExport(root, options?): void`, `SaveExportOptions`, `defaultTriggerDownload(text, fileName): void`, `renderUndoRedoControls(root, options?): UndoRedoControlsHandle`, `UndoRedoControlsOptions`, `UndoRedoControlsHandle`

`save-export.ts` calls `document.markLifebarDocumentSaved()` on a
successful export (never on a blocked one) — item 006's New Lifebar
Wizard reads that same store's `hasUnsavedLifebarChanges()` for its own
discard guard, so a save clears that warning without a reload.
**Depends on:** `modules/lifebar.md` (`LifebarDocument`/`LifebarSection` types, `serializeLifebar`), `modules/wasm.md` (`SpriteGroup`/`Sprite` types), `modules/document.md` (the document/sprite-sheet stores `save-export.ts` reads from, and `undo-redo-controls.ts`'s default `CommandStack`)
