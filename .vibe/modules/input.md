# Module: input
**Role:** Two independent inputs, both wholesale-replacing their previous outcome on every new load (unlike `character-editor`'s accumulating multi-slot input): a folder-based lifebar input (backlog item 011 — folder selection is the only way to load a lifebar on the web build, replacing item 002's single-file picker/drop zone) that gathers a selected/dropped folder's files, resolves which one is the lifebar's own `.def`-style file (auto-picking a sole candidate or asking the user to choose among several), reads it as text and parses it; and a single-file sprite sheet input, unaffected by that change — reads the selected/dropped `.sff` file's bytes and loads it via `wasm`, distinguishing a read failure, the WASM module failing to start (setup-error), and the module reporting a malformed file (parse-error).
**Files:** `src/input/folder-entries.ts`, `src/input/lifebar-folder-input.ts`, `src/input/lifebar-folder-input-view.ts`, `src/input/sprite-sheet-input.ts`, `src/input/sprite-sheet-input-view.ts`
**Exports:** `filesFromWebkitDirectoryFiles(files): GatheredFile[]`, `filesFromDataTransferItems(items): Promise<GatheredFile[]>`, `collectFilesFromEntry(entry): Promise<GatheredFile[]>`, `GatheredFile`, `resolveCandidates(files): CandidateResolution`, `loadLifebarFromFolderFiles(files, options?): Promise<LifebarFolderInputResult>`, `loadLifebarFromChosenEntry(entry, options?): Promise<LifebarFolderInputResult>`, `readFileAsText(file): Promise<string>`, `LifebarFolderInputResult`, `LifebarFolderInputOptions`, `renderLifebarFolderInput(root, options): void`, `LifebarFolderInputViewOptions`, `loadSpriteSheetFromFile(file, options?): Promise<SpriteSheetInputResult>`, `readFileAsBytes(file): Promise<Uint8Array>`, `SpriteSheetInputResult`, `SpriteSheetInputOptions`, `renderSpriteSheetInput(root, options): void`, `SpriteSheetInputViewOptions`
**Depends on:** `modules/lifebar.md`, `modules/wasm.md`, `modules/viewer.md`, `modules/i18n.md` (each view's own static/status text; each subscribes to `onLocaleChange` once, internally, re-formatting its currently-shown status from a small stored descriptor rather than re-reading/re-parsing the file)
