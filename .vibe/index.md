## Observed patterns
- TypeScript with `strict`, `noUnusedLocals`, `noUnusedParameters` enabled (`tsconfig.json`)
- Explicit `.ts` extensions on relative imports (`allowImportingTsExtensions`)
- Test files co-located with source as `*.test.ts`, using Vitest + jsdom
- Whether `web-ui-kit`'s design tokens stylesheet actually loaded is detected by probing a known `--wuik-*` custom property via `getComputedStyle`, not a stylesheet load/error event — a failed load degrades to a plain, dependency-free error state instead of a broken or blank shell
- A format this app doesn't fully interpret yet is modeled as ordered lists of raw, unevaluated key/value data rather than typed fields per known key — mirrors the sibling `character` Go library's own `.cns`/`.cmd` controller philosophy, and is what makes an unrecognized (e.g. Ikemen-only) section/key round-trip through unchanged for free
- Sections/entries in a format that can legitimately repeat a name/key are stored as ordered arrays, never a `Record`/`Map`, which would silently drop a duplicate
- File bytes/text are read via `FileReader` (`readAsText` here, `readAsArrayBuffer` in sibling apps) rather than the `Blob` read methods, since the project's pinned jsdom version has an incomplete `Blob` implementation — the same real-browser/jsdom parity concern recurs across every OpenKakutou editor/viewer app
- The DOM-building logic of a screen/component is a pure exported function (`renderApp(root, version, options?)`, `renderLifebarFileInput(root, options)`) taking its target element and data/callbacks as parameters, kept separate from the module-level bootstrap — same "inject external effects for testability" shape applied to DOM construction
- Module-level, in-process application state with no external effect to substitute in tests (`src/document/lifebar-document-store.ts`) is a plain get/set pair with a test-only reset function, mirroring `character-editor`'s own `character-document.ts`
- A single-file input (this app) is a wholesale-replace state machine (idle/loading/success/error, new drop discards the previous outcome), distinct from a multi-file accumulating input (`character-editor`'s own file input) — the two are deliberately different interaction models for different-shaped problems, not a missed convention
